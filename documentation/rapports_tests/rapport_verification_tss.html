Conclusion

  • Critère satisfait. Pour chaque sport, l'app applique la formule attendue et sélectionne le bon tss_type ; à défaut de donnée propre, elle retombe correctement sur le hrTSS.
  • Fidélité parfaite : 15/15 cas testés via Playwright et 2/2 cas natation (moteur) reproduisent la formule à 0,00 % près (seul l'arrondi entier s'applique, identique au calcul manuel).
  • Sélection du type : 17/17 corrects — tss (vélo), rtss (course), hrtss (FC + replis), rpe, estimated, stss (natation).
  • Seul point ouvert : la natation étant exclue du formulaire manuel, son type stss n'est validable qu'à l'import — pas un bug de calcul, une couverture UI à compléter si la saisie manuelle de natation devient nécessaire.

Méthodologie : référence = formule TrainingPeaks calculée à la main avec des inputs choisis pour donner des IF « ronds » (valeurs connues exactes). Mesure = 15 séances créées dans le formulaire de création manuelle de l'app (Playwright, session réelle authentifiée), tss et tss_type relus en base — le calcul étant celui du code de production (src/lib/calculations/training-load.ts → calculateActivityTSS, commun import + manuel). La natation (stss) a été vérifiée via le moteur verbatim faute de sport correspondant dans le formulaire. Séances de test et seuils temporaires supprimés après mesure.
