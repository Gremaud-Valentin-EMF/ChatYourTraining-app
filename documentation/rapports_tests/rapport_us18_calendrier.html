Conclusion

  • Critères satisfaits : 4/4. CA1 (pastilles enrichies : titre + icône + durée + statut), CA2 (détail journée : séances + météo + fatigue + notes), CA3 (séance → détail + « Marquer comme fait » si passée/aujourd'hui), CA4 (message exact pour une semaine vide).
  • Implémentation : composant SessionChip piloté par le statut, ajout de l'icône du sport au chargement, bannière de semaine vide et libellés d'accessibilité sur la navigation. CA2/CA3 déjà couverts par l'existant (panneau jour + /workouts/[id]).
  • Qualité : tsc --noEmit et eslint sans erreur ; aucune modification backend.

Méthodologie : 3 séances du jour (planifiée / faite / manquée) créées en base via le client service-role, puis 4 tests Playwright sur une session réelle authentifiée valident chaque critère sur /calendar et /workouts/[id] (e2e/calendar.spec.ts). Météo non disponible en test faute de géolocalisation — l'app affiche le repli prévu. Données de test re-seedées à chaque exécution.
